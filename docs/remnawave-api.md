## Remnawave API Integration Guide

This document explains **how this bot talks to the Remnawave backend API**, what is configured via `.env`, and which parts of the Remnawave API surface are used. It is intended as a reference when making major changes to user / subscription behaviour.

---

## 1. Overview

- **Backend**: Remnawave panel API  
- **Docs**: public API spec at [`https://docs.rw/api/`](https://docs.rw/api/)  
- **Go SDK**: [`github.com/Jolymmiles/remnawave-api-go/v2`](https://github.com/Jolymmiles/remnawave-api-go)  
- **Local client wrapper**: `internal/remnawave/client.go`

All Remnawave calls go through the local `Client` type, which wraps the official Go SDK:

```1:61:internal/remnawave/client.go
type Client struct {
	client *remapi.ClientExt
}

func NewClient(baseURL, token, mode string) *Client {
	// baseURL: REMNAWAVE_URL
	// token:   REMNAWAVE_TOKEN (JWT or API token)
	api, err := remapi.NewClient(baseURL, remapi.StaticToken{Token: token}, remapi.WithClient(httpClient))
	return &Client{client: remapi.NewClientExt(api)}
}
```

The SDK itself is generated from the official Remnawave OpenAPI spec using `ogen` and exposes typed sub‑clients like:

- `client.Users()` – user management (create, list, get by Telegram ID, update)
- `client.InternalSquad()` – internal squad list

These correspond directly to the HTTP endpoints described in the Remnawave API docs.

## 2. Configuration: how `.env` controls the API

Relevant `.env` variables (see `.env.sample`):

```1:34:.env.sample
REMNAWAVE_URL=https://example.com
REMNAWAVE_MODE=remote
REMNAWAVE_TOKEN=token
SQUAD_UUIDS=
EXTERNAL_SQUAD_UUID=
REMNAWAVE_TAG=TEST_PUPA
TRIAL_REMNAWAVE_TAG=
TRIAL_INTERNAL_SQUADS=
TRIAL_EXTERNAL_SQUAD_UUID=
TRAFFIC_LIMIT=100
TRIAL_TRAFFIC_LIMIT=20
TRIAL_DAYS=2
TRAFFIC_LIMIT_RESET_STRATEGY=MONTH
TRIAL_TRAFFIC_LIMIT_RESET_STRATEGY=MONTH
REMNAWAVE_HEADERS=
```

Mapped in `internal/config/config.go`:

- **Base connection**
  - `REMNAWAVE_URL` → `config.RemnawaveUrl()` – API base URL
  - `REMNAWAVE_TOKEN` → `config.RemnawaveToken()` – bearer token for SDK
  - `REMNAWAVE_MODE` → `config.RemnawaveMode()` – `"remote"` or `"local"`; `"local"` injects `x-forwarded-for` / `x-forwarded-proto` headers to simulate HTTPS.
  - `REMNAWAVE_HEADERS` → `config.RemnawaveHeaders()` – arbitrary extra headers (e.g. `X-Api-Key`), added by `headerTransport`.

- **Traffic and duration**
  - `TRAFFIC_LIMIT` (GB) → `config.TrafficLimit()` (bytes) – base traffic cap for paid users.
  - `TRIAL_TRAFFIC_LIMIT` (GB) → `config.TrialTrafficLimit()` (bytes) – traffic for trial users.
  - `TRIAL_DAYS` → `config.TrialDays()` – number of days for trial access.
  - `DAYS_IN_MONTH` → `config.DaysInMonth()` – used to convert “months” from purchases to days when extending subscriptions.

- **Reset strategy**
  - `TRAFFIC_LIMIT_RESET_STRATEGY` → `config.TrafficLimitResetStrategy()` – `"DAY" | "WEEK" | "MONTH" | "NO_RESET"`.
  - `TRIAL_TRAFFIC_LIMIT_RESET_STRATEGY` → `config.TrialTrafficLimitResetStrategy()`.

- **Squads and tagging**
  - `SQUAD_UUIDS` → `config.SquadUUIDs()` – **whitelist** of internal squad UUIDs used for regular users.
  - `EXTERNAL_SQUAD_UUID` → `config.ExternalSquadUUID()` – optional external squad attached to all paid users.
  - `TRIAL_INTERNAL_SQUADS` → `config.TrialInternalSquads()` – override internal squads for trial users (fallback to `SQUAD_UUIDS` if empty).
  - `TRIAL_EXTERNAL_SQUAD_UUID` → `config.TrialExternalSquadUUID()` – override external squad for trial users.
  - `REMNAWAVE_TAG` → `config.RemnawaveTag()` – tag string attached to all paid users.
  - `TRIAL_REMNAWAVE_TAG` → `config.TrialRemnawaveTag()` – tag string attached to trial users only (fallback to `REMNAWAVE_TAG`).

When you change these `.env` values, you are configuring **how Remnawave users are created/updated**, not just the Telegram bot.

## 3. User lifecycle in Remnawave

From this bot’s perspective, a “user” in Remnawave has at least:

- `UUID` – internal Remnawave user ID.
- `Username` – generated by this bot as `<customer_id>_<telegram_id>`.
- `TelegramId` – Telegram chat ID.
- `ExpireAt` – subscription expiration timestamp.
- `SubscriptionUrl` – link used by the VPN app / client.
- `TrafficLimitBytes` – traffic cap in bytes.
- `TrafficLimitStrategy` – reset policy (DAY/WEEK/MONTH/NO_RESET).
- `ActiveInternalSquads` – list of internal squad UUIDs (connection methods).
- `ExternalSquadUuid` – optional single external squad.
- `Tag` – arbitrary string, configured via `REMNAWAVE_TAG` / `TRIAL_REMNAWAVE_TAG`.

### 3.1 Single user per Telegram account

The bot follows a **single-user-per-Telegram-account** model in Remnawave:

- All creations and updates go through `Client.CreateOrUpdateUser`.
- Users are always looked up by **Telegram ID** (`GetUserByTelegramId`).
- If at least one user exists for that Telegram ID, the bot **updates** that user instead of creating a new one.
- If no user exists, the bot creates a new one with username `<customer_id>_<telegram_id>`.

This means:

- Free plan activation, Lite / Max purchases, upgrades, and renewals all operate on **the same Remnawave user**.
- The VPN **subscription link** (`SubscriptionUrl`) is conceptually permanent for that Telegram account. When Remnawave returns a new `SubscriptionUrl`, the bot overwrites the single `customer.subscription_link` field, and `My Links` / `Profile` always show the latest value.
- There is **no separate Remnawave user per tier**; only the traffic limits, squads, and expiration are changed over time.

### 3.2 Creating a user

Creation is done via `Client.createUser`, which calls the SDK’s `Users().CreateUser`:

```231:304:internal/remnawave/client.go
func (r *Client) createUser(ctx context.Context, customerId int64, telegramId int64, trafficLimit int, days int, isTrialUser bool) (*remapi.User, error) {
	expireAt := time.Now().UTC().AddDate(0, 0, days)
	username := generateUsername(customerId, telegramId) // "<customerId>_<telegramId>"

	resp, err := r.client.InternalSquad().GetInternalSquads(ctx)
	// ...
	createUserRequestDto := remapi.CreateUserRequestDto{
		Username:             username,
		ActiveInternalSquads: squadId,          // filtered by SQUAD_UUIDS / TRIAL_INTERNAL_SQUADS
		Status:               ACTIVE,
		TelegramId:           telegramId,
		ExpireAt:             expireAt,
		TrafficLimitStrategy: getCreateStrategy(strategy), // from TRAFFIC_LIMIT_RESET_STRATEGY / TRIAL_*
		TrafficLimitBytes:    trafficLimit,
		ExternalSquadUuid:    externalSquad,               // EXTERNAL_SQUAD_UUID / TRIAL_EXTERNAL_SQUAD_UUID
		Tag:                  tag,                         // REMNAWAVE_TAG / TRIAL_REMNAWAVE_TAG
		Description:          telegram username (if known),
	}
	userCreate, err := r.client.Users().CreateUser(ctx, &createUserRequestDto)
	return &userCreate.(*remapi.UserResponse).Response, nil
}
```

**Called from:**

- `PaymentService.ProcessPurchaseById` for **paid** subscriptions:
  - `trafficLimit = config.TrafficLimit()`
  - `days = purchase.Month * config.DaysInMonth()`
  - `isTrialUser = false`
- `PaymentService.ActivateTrial` for **trial** subscriptions:
  - `trafficLimit = config.TrialTrafficLimit()`
  - `days = config.TrialDays()`
  - `isTrialUser = true`

If a user with that Telegram ID already exists, the bot will **update** instead of creating (see below).

### 3.3 Updating a user (extend / change subscription)

Updates are handled by `Client.updateUser`, which calls `Users().UpdateUser`:

```165:229:internal/remnawave/client.go
func (r *Client) updateUser(ctx context.Context, existingUser *remapi.User, trafficLimit int, days int) (*remapi.User, error) {
	newExpire := getNewExpire(days, existingUser.ExpireAt)

	resp, err := r.client.InternalSquad().GetInternalSquads(ctx)
	// build squadId slice filtered by SQUAD_UUIDS

	userUpdate := &remapi.UpdateUserRequestDto{
		UUID:                 existingUser.UUID,
		ExpireAt:             newExpire,
		Status:               ACTIVE,
		TrafficLimitBytes:    trafficLimit,
		ActiveInternalSquads: squadId,
		TrafficLimitStrategy: getUpdateStrategy(config.TrafficLimitResetStrategy()),
		ExternalSquadUuid:    EXTERNAL_SQUAD_UUID (if set),
		Tag:                  REMNAWAVE_TAG (if set),
		Description:          telegram username (if known),
	}

	updateUser, err := r.client.Users().UpdateUser(ctx, userUpdate)
	return &updateUser.(*remapi.UserResponse).Response, nil
}
```

`getNewExpire` encapsulates the **extension logic**:

- For positive `daysToAdd`:
  - If `ExpireAt` is in the past or zero → start from **now**.
  - Else → extend from current `ExpireAt`.
- For `daysToAdd <= 0`:
  - If result would be in the past → clamp to “tomorrow” (now + 1 day).
  - Else → shift from current `ExpireAt`.

This is what actually makes “1 / 3 / 6 / 12 month” purchases extend the subscription in Remnawave.

### 3.4 Lookup by Telegram ID

Both `CreateOrUpdateUser` and `DecreaseSubscription` lookup Remnawave users by Telegram ID:

```132:163:internal/remnawave/client.go
resp, err := r.client.Users().GetUserByTelegramId(ctx, strconv.FormatInt(telegramId, 10))
usersResp := resp.(*remapi.UsersResponse)
users := usersResp.GetResponse()

if len(users) == 0 {
	// no users -> create new
}

// Prefer username that ends with "_<telegramId>"
suffix := fmt.Sprintf("_%d", telegramId)
for i := range users {
	if strings.Contains(users[i].Username, suffix) {
		existingUser = &users[i]
		break
	}
}
if existingUser == nil {
	existingUser = &users[0]
}
```

This corresponds to an underlying Remnawave endpoint similar to:

- `GET /users?telegramId=<id>` (exact shape see official docs).

## 4. Where Remnawave is used in the bot

High‑level integration points:

- **Payment processing** (`internal/payment/payment.go`)
  - `ProcessPurchaseById`:
    - Calls `remnawaveClient.CreateOrUpdateUser(...)` to apply the purchased duration and traffic limit.
    - After successful update, stores `subscription_link` and `expire_at` from the Remnawave user into the local `customer` record.

- **Trials** (`PaymentService.ActivateTrial`)
  - Same flow as paid, but with trial‑specific traffic, days, tags, squads, and strategies.

- **Tribute cancel / DecreaseSubscription**
  - `PaymentService.CancelTributePurchase` calls `remnawaveClient.DecreaseSubscription`, which:
    - Locates the Remnawave user by Telegram ID.
    - Calls `updateUser` with **negative days** to shorten the subscription.

- **Sync service** (`internal/sync/sync.go`)
  - `SyncService.Sync`:
    - Uses `remnawaveClient.GetUsers(ctx)` (pagination over `Users().GetAllUsers`) to fetch **all** Remnawave users.
    - Maps them into local `customer` records (`telegram_id`, `expire_at`, `subscription_link`).
    - Deletes local customers that no longer exist in Remnawave and creates/updates those that do.

Together, these mean: **Remnawave is the source of truth for subscription state**, while the local DB is a cache/replica optimised for bot behaviour.

## 5. Making changes safely

When you want to change how this bot uses the Remnawave API, follow this checklist:

1. **Confirm API behaviour** in the official docs  
   - Go to [`https://docs.rw/api/`](https://docs.rw/api/) and locate the relevant endpoints under “Users”, “InternalSquad”, etc.
   - Cross‑check with the Go SDK methods you plan to use (`client.Users().Xxx`, `client.InternalSquad().Xxx`).

2. **Update the local wrapper (`internal/remnawave/client.go`) first**  
   - Add new helper methods here instead of calling the SDK directly from handlers/services.
   - Keep username / telegram ID lookup and squad selection logic centralised.

3. **Wire changes into services**  
   - Subscription creation / extension → `PaymentService` and `NotificationService`.
   - Bulk synchronisation → `SyncService`.

4. **Keep `.env` and `config` in sync**  
   - If the API starts supporting new flags (e.g. new traffic strategies, new tags), add them as env vars in `.env.sample` and expose via `internal/config`.

5. **Test against a staging panel**  
   - Point `REMNAWAVE_URL` and `REMNAWAVE_TOKEN` to a staging / test Remnawave instance.
   - Use a test bot and accounts to verify user creation, extension, and sync before deploying to production.

This document should give you enough context to confidently evolve the bot’s behaviour while staying compatible with the official Remnawave API and its SDK.
